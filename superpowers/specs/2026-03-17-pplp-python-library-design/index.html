    PPLP Python Library — Design Spec¶

    Summary¶

    A Python library implementing privacy-preserving link prediction (Common Neighbors) for two-party distributed graphs, based on Demirag/Ayday et al. 2022. Uses OpenMined PSI for cardinality-only private set intersection. Local-only execution initially; networking layer deferred to a future phase.

    Package Structure¶

    lib/
    pplp/
        __init__.py          # public API exports
        graph.py             # Graph class
        protocol.py          # compute_cn() orchestration
        psi.py               # OpenMined PSI wrapper
pyproject.toml               # uv-managed project

    Dependencies¶

    • openmined-psi — ECDH-based PSI with cardinality-only mode (C++ backend, pip-installable, macOS ARM + Linux)
    • networkx (optional) — only needed for Graph.from_networkx() convenience method
    • Managed via uv with pyproject.toml

    Components¶

    graph.py — Graph class¶

    Thin wrapper around an adjacency list (dict[str, set[str]]). Node IDs are strings (parties agree on identifiers per paper assumptions).

    Methods: - neighbors(node: str) -> set[str] — return neighbor set - local_intersection(x: str, y: str) -> set[str] — return Gamma(x) & Gamma(y) - has_edge(x: str, y: str) -> bool - add_edge(u: str, v: str) — add undirected edge - from_edge_list(edges: list[tuple[str, str]]) -> Graph — class method - from_networkx(G: nx.Graph) -> Graph — class method

    psi.py — PSI wrapper¶

    Single function isolating the OpenMined PSI dependency:

    def psi_cardinality(set_a: set[str], set_b: set[str]) -> int

    Runs OpenMined PSI client/server in-process with reveal_intersection=False (cardinality-only). Returns the intersection size. Short-circuits to 0 if either input set is empty.

    This isolation means swapping PSI backends or adding networking only touches this file.

    protocol.py — Protocol orchestration¶

    Single function implementing the Demirag/Ayday et al. protocol. graph1 is the client/requester (learns the result), graph2 is the server/helper (learns nothing). This asymmetry mirrors the paper's model and matters for the future networking layer.

    def compute_cn(graph1: Graph, graph2: Graph, x: str, y: str) -> int

    Steps: 1. Validate preconditions: - If x-y are direct neighbors in graph1, raise/return early (Graph 1 has no need for the computation) - If x-y are direct neighbors in graph2, return a sentinel or raise indicating a direct link was found (per paper Section 2.2, assumption 4: Graph 2 halts and informs Graph 1) - If a node is absent from a graph, treat its neighbor set as empty (the protocol still works with zero-cardinality contributions) 2. Compute local intersections: - local1_set = graph1.local_intersection(x, y) - local2_set = graph2.local_intersection(x, y) - local1 = len(local1_set), local2 = len(local2_set) 3. Compute reduced neighbor sets (remove local intersection members): - g1_x = graph1.neighbors(x) - local1_set - g1_y = graph1.neighbors(y) - local1_set - g2_x = graph2.neighbors(x) - local2_set - g2_y = graph2.neighbors(y) - local2_set 4. Three PSI-cardinality calls: - crossover1 = psi_cardinality(g1_x, g2_y) - crossover2 = psi_cardinality(g1_y, g2_x) - overlap = psi_cardinality(local1_set, local2_set) 5. Return local1 + local2 + crossover1 + crossover2 - overlap

    __init__.py — Public API¶

    Exports: Graph, compute_cn, DirectLinkFound

    Testing¶

    • Paper example: Reproduce Figure 6 from Demirag/Ayday et al. (nodes 1 and 6, expected CN=3)
    • Correctness check: Compare compute_cn output against a plain (non-private) common neighbor computation on the merged graph for various test cases
    • Edge cases: Empty neighbor sets, no overlap between graphs, single-node intersections

    Future Work (not in scope)¶

    • Network layer: socket/gRPC communication so Graph 1 and Graph 2 run on separate machines
    • Additional similarity metrics: Jaccard, Adamic-Adar
    • Streamlit web dashboard
    • Heavier homomorphic variant (zero leakage, per Section 4.1 of the paper)
